## os and io: summary

- `os.getenv` is +26% instructions and `os.time` on a reused table is 1.85× reference. The latter is primarily an inverse-timezone search, not the shared cache lock (high confidence).
- Throwaway prototypes save about 80M instructions per 2M HOME lookups and 147M per 100k Chicago time conversions; targets are ~1,210M and ~730M respectively, not full parity.
- The historical `file_lines` 1.2× cycle / 750k cache-miss gap did **not** recur. L1 miss variation is real and buffer-sensitive; the mutex is not established as the cause (medium confidence; shared machine).
- `iobench` has a real but tiny opposing VM-phase effect; the apparent large threaded/switch difference is dominated by hash/layout variation (high confidence for tested seeds).

## Causes

- `os_getenv` directly calls the same glibc getenv as C. `oslib.odin` constructs a full default Context, checks the argument, scans the returned C string byte-by-byte (`string(value)`), interns/copies it and runs the normal GC checkpoint. The hot disassembly contains 19 Context-initialization instructions per call (about 38M/2M calls), excluding the prologue; the scalar length loop is additional. These counts describe the current binary, not a removable cost under the Context rules. Native and table dispatch also account for a significant part of the gap.
- `timestamp_from_loaded_zone` tries every candidate offset, calls timezone selection and eagerly computes a complete `Civil_Time` for each candidate even when its wall time cannot win. `os_time` must also read six fields plus `isdst` and write nine normalized fields via the public API, as `loslib.c` does; metamethods and observable mutation prevent simply bypassing these operations.
- For file lines, the previously reported excess generic cache misses is not reproducible here; shared-core interference and PMU skid are plausible but not proven explanations. The buffer-size controls establish a substantial L1 component; repeated vs unique strings and GC profiles show a separate allocation/interning component. The mutex removal control changes instructions/cycles but barely changes L1 misses; it cannot establish a safe optimization or explain the historical 750k misses. Glibc `flockfile` on this machine also locks, with a guarded single-thread fast path.
- The iobench per-phase VM differences are real at matched paths but nearly cancel. The 1/100 Callgrind comparison locates a seed-sensitive difference in API table lookup; common I/O function self counts match at fixed seed. Hand off possible `TFORCALL`/native boundary work to the calls analyst, not an I/O rewrite.

## Levers

1. **Defer civil conversion in inverse search** (`src/stdlib/oslib.odin`). When `got_nominal == nominal`, reuse the already-normalized wall fields; otherwise construct a civil result only if the candidate can replace a best result. Keep candidate order, DST preference, gaps/folds, returned fields and lock scope exactly. Measured Chicago reuse 867.2→720.5M (−16.9%), varying seconds 886.8→740.2M; UTC 547.1→532.1M, POSIX DST 718.5→700.3M. Randomized baseline differential: 72,120 cases across eight zones and explicit/implicit DST, plus time roundtrip, −1 and concurrent-state unit tests passed. Risk: unusual historical TZif types and correctness-tz changes; coordinate before landing. New lever, not a FUTURE_WORK dead end.
2. **Linux getenv length and checked argument** (`src/stdlib/oslib.odin`, Linux-only helper if needed). Use existing `native_checklstring` with a real Context, and libc `strlen` on the terminated host result rather than Odin's scalar C-string conversion before the normal `api_pushstring`. Measured 2M HOME baseline/native/native+strlen 1,286.7/1,248.7/1,206.7M; a 100-byte value 2,776.7/2,758.7/2,000.7M. Empty value combined prototype 1,708.7 vs baseline 1,716.7M; do not assume the strlen call helps every size. Prototype passed present/empty/absent/invalid/NUL Lua cases and getenv values, finalizer, 4KiB temporary-arena unit tests. Preserve numeric coercion, rooted input, host getenv semantics, copy before GC/finalizers, OOM, empty-vs-nil, Linux no-CRT and Windows paths. Context cannot just be removed around OS calls/allocation. Distinct from e690eb8, which already removed the environment copies; not a listed dead end.
3. **Investigate buffer size/locality, not lock removal** (`src/stream/stream.odin`, `bench`, `tests`). 16 KiB measured −0.425M L1 misses and −1.15M instructions on `file_lines`, but cycles only ~1M lower and memory +16 KiB per stream. Estimate real-world benefit unknown. Test 4/8/16 KiB, aligned vs varied placement, read/write/short/long files and memory/open-stream scaling on a quiet machine; only change a default if cycles and memory justify it. Preserve `setvbuf`, exact positions, pushback, EOF, CRLF/Ctrl-Z and error semantics. No listed dead end.
4. **Only investigate a provably safe uncontended lock fast path** if quiet measurements justify it. The unsafe control removes ~18M instructions / 200k lines, an indicative ceiling for omitting the current read lock alone (with possible code-layout effects); a guarded design is likely to save less. Glibc's `__libc_single_threaded` fast path is a comparison, not permission to assume an embedding process is single-threaded. Any design must retain d3dc2c2 stream/list/pin semantics, interoperation with process-wide flush, independent Lua states, host-created threads, and no Lua calls under a held lock. Fall back on Windows/other hosts; avoid the recursive-mutex dead end documented in d3dc2c2. Do not trade safety for this speculative gain.
5. **Later timezone-cache experiment**, jointly with correctness-tz: cache validated/deduplicated `(offset, isdst)` candidates or safe recurring-rule intervals on zone load, retaining first-candidate tie order and invalidation. Per-call linear dedup after lever 1 only improved Chicago 720.5→714.8M and worsened POSIX varying 700.3→705.9M; do not repeat it as the final design. Cache-time precomputation is a different, unmeasured idea. Malformed files, 256-type zones, POSIX footer boundaries and concurrent TZ changes are high risk.
